# Iリスト 帳票アプリ

自動車型式の **適合必要法規** と **認証取得実績（認可書）** を管理する帳票。
規制日に対して、各型式が適合すべき法規の漏れを検出し、認証取得実績を一元管理する。
エクセルの「塗り絵」運用を、リレーショナルなデータモデルと自動判定に置き換える。

## 動かす（Mac）

Node.js が必要（未インストールなら https://nodejs.org からLTS版を入れる）。

```bash
cd ilist-app
npm install      # 初回だけ。依存をダウンロード
npm run dev      # 画面(Vite)とAPIサーバ(SQLite保存)を同時起動
```

ターミナルに出る `http://localhost:5173` をブラウザで開く。
コードを編集すると自動で反映される（ホットリロード）。

止めるときは `Ctrl + C`。

**データは編集すると自動でサーバに保存される**（画面右上に保存状態が出る）。
保存先は `data/ilist.db`（SQLiteファイル1個）。このファイルをコピーすればバックアップになる。

### 本番モード（ビルドして1プロセスで動かす）
```bash
npm run build    # dist/ に静的ファイルが出る
npm run server   # http://localhost:3001 だけで画面もAPIも動く
```

同じネットワークの人に `http://<自分のMacのIP>:3001` を開いてもらえば共有もできる
（ただし同時編集の衝突対策はまだ無い。後から保存した人が勝つ）。

## 構成

```
ilist-app/
├── index.html          エントリ
├── package.json        依存とスクリプト
├── vite.config.js      Vite設定（/api をバックエンドへプロキシ）
├── server/
│   └── index.js        APIサーバ（node:http + node:sqlite。追加ライブラリ不要）
├── data/
│   └── ilist.db        SQLiteデータベース（自動生成。gitには入れない）
└── src/
    ├── main.jsx        Reactマウント
    └── IListApp.jsx    アプリ本体（4タブ＋判定エンジン＋自動保存）
```

依存は `react` と `lucide-react`（アイコン）のみ（開発用に `concurrently` を追加）。
バックエンドはNode標準機能だけで動く。Tailwind等は不使用（インラインstyle）。

### API

- `GET /api/data` … `{ runs, regs, cert }` を返す
- `PUT /api/data` … 全置換で保存（トランザクション）

## 機能

4タブ構成。

- **帳票**：型式×法規のマトリクス。要否・申請発生・実効ドロップを自動算出。
- **型式ラン**：型式・プロジェクト世代・新継・LO・ドロップを編集。
- **法規DB**：法規ID・新型適用日・継続適用日・シリーズアップ元を編集。
- **認可書実績**：型式×法規に認可書番号を入力。

編集は**自動でサーバ（SQLite）に保存**される。ブラウザを閉じても、サーバやMacを再起動しても残る。
右上の **JSON書き出し／読み込み** はバックアップ・持ち運び用として残している
（読み込むと、その内容がそのままサーバに自動保存される）。

## 判定ロジック（コア）

要否は2種類の判定を持つ。見る日付が新継で切り替わる。

```
新型ラン：要 ⇔ (新型適用日 ≤ LO) OR (継続適用日 ≤ ドロップ)
継続ラン：要 ⇔  継続適用日 ≤ ドロップ
```

- 新型車の最初の適合は LO（ラインオフ）起点。ラインオフ確定で適合法規が確定する。
- 継続生産車の対応はドロップ（生産終了）起点。生産を続ける限り発効した継続規制に適合が必要。
- 新型車も生産を続ける以上、継続規制についてはドロップ日も見る（長期生産で起きうる）。

### データの粒度

```
型式 × プロジェクト（時間軸）× 法規
```

認証単位は型式（類別は持たない）。新継は型式登場、生産窓はプロジェクト、認可書実績は型式に直付け。

### 範囲外
extension申請・ランニングチェンジ（起点は前工程）、類別・諸元表（M精査の領域）。

## ロードマップ

- **段階1 ✅**：画面入力＋JSON保存で動く帳票。判定エンジン完成。
- **段階2 ✅**：サーバ保存。Node + SQLite のバックエンドを追加し、編集を自動で永続化。
- **段階3**：指定装置一覧Excel(.xlsx)の取り込み → 認可書実績を自動充足。
  D列の認可番号をパースして法規ID＋シリーズを抽出、G列以降のマトリクスから車両型式×法規を引き当てる。
- **段階4**：本格的な複数人運用（同時編集の衝突対策・ユーザー管理・権限）。
  会社の機微情報を扱うため、情報システム/セキュリティの承認が前提。

## 残論点
- シリーズアップ（例 R46-04 → R46-05）：最新シリーズの取得で旧シリーズ行を充足扱いにするか、各行を独立管理するか。現状は独立判定。
