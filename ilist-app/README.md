# Iリスト 帳票アプリ

自動車型式の **適合必要法規** と **認証取得実績（認可書）** を管理する帳票。
規制日に対して、各型式が適合すべき法規の漏れを検出し、認証取得実績を一元管理する。
エクセルの「塗り絵」運用を、リレーショナルなデータモデルと自動判定に置き換える。

## 動かす（Mac）

Node.js が必要（未インストールなら https://nodejs.org からLTS版を入れる）。

```bash
cd ilist-app
npm install      # 初回だけ。依存をダウンロード
npm run dev      # 開発サーバ起動
```

ターミナルに出る `http://localhost:5173` をブラウザで開く。
コードを編集すると自動で反映される（ホットリロード）。

止めるときは `Ctrl + C`。

### 本番ビルド（任意）
```bash
npm run build    # dist/ に静的ファイルが出る
npm run preview  # ビルド結果を確認
```

依存は `react` と `lucide-react`（アイコン）のみ。Tailwind等は不使用（インラインstyle）。

## 機能（段階1）

4タブ構成。

- **帳票**：型式×法規のマトリクス。要否・申請発生・実効ドロップを自動算出。
- **型式ラン**：型式・プロジェクト世代・新継・LO・ドロップを編集。
- **法規DB**：法規ID・新型適用日・継続適用日・シリーズアップ元を編集。
- **認可書実績**：型式×法規に認可書番号を入力。

右上から **JSON書き出し／読み込み** でデータを手元に保存・復元できる。

## 判定ロジック（コア）

要否は2種類の判定を持つ。見る日付が新継で切り替わる。

```
新型ラン：要 ⇔ (新型適用日 ≤ LO) OR (継続適用日 ≤ ドロップ)
継続ラン：要 ⇔  継続適用日 ≤ ドロップ
```

- 新型車の最初の適合は LO（ラインオフ）起点。ラインオフ確定で適合法規が確定する。
- 継続生産車の対応はドロップ（生産終了）起点。生産を続ける限り発効した継続規制に適合が必要。
- 新型車も生産を続ける以上、継続規制についてはドロップ日も見る（長期生産で起きうる）。

### データの粒度

```
型式 × プロジェクト（時間軸）× 法規
```

認証単位は型式（類別は持たない）。新継は型式登場、生産窓はプロジェクト、認可書実績は型式に直付け。

### 範囲外
extension申請・ランニングチェンジ（起点は前工程）、類別・諸元表（M精査の領域）。

## ロードマップ

- **段階1（このリポジトリ）**：画面入力＋JSON保存で動く帳票。判定エンジン完成。
- **段階2**：指定装置一覧Excel(.xlsx)の取り込み → 認可書実績を自動充足。
  D列の認可番号をパースして法規ID＋シリーズを抽出、G列以降のマトリクスから車両型式×法規を引き当てる。
- **段階3**：DB化・複数人・権限。会社の機微情報を扱うため、情報システム/セキュリティの承認が前提。

## 残論点
- シリーズアップ（例 R46-04 → R46-05）：最新シリーズの取得で旧シリーズ行を充足扱いにするか、各行を独立管理するか。現状は独立判定。
